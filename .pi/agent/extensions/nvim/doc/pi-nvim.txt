*pi-nvim*  Manage Pi from Neovim

                      *pi-nvim-intro*
pi-nvim provides a managed Pi terminal, prompt and visual-selection transfer
to Pi's interactive input, and a quickfix list of file references from the
latest completed Pi response. The companion Pi extension is required for
prompt/selection transfer and reference updates.

==============================================================================
1. Setup                                                       *pi-nvim-setup*

Requirements: Neovim 0.10 or newer, Pi available as `pi` (or a configured
command), and the companion extension loaded by Pi.

Add the project to the Neovim runtime path using your plugin manager. For
lazy.nvim with this local checkout:

    {
        dir = "~/Projects/pi-nvim",
        name = "pi-nvim",
        lazy = false,
        config = function()
            require("pi_nvim").setup({
                provider = vim.env.LLM_PROVIDER,
                model = vim.env.LLM_MODEL,
            })
        end,
    }

Add the extension source to the `extensions` array in
`~/.pi/agent/settings.json`:

    {
      "extensions": [
        "~/Projects/pi-nvim/pi/index.ts"
      ]
    }

Merge the extension path with any existing entries. The root `package.json`
declares `pi/index.ts` as the project extension entry point. Pi must load this
extension for prompt/selection transfer and reference updates; terminal
management itself does not depend on the extension.

If `provider` is set in setup, `model` must also be set. The values are passed
to the managed Pi process as `--provider` and `--model` arguments.

==============================================================================
2. Configuration                                     *pi-nvim-configuration*

Call `require("pi_nvim").setup(opts)` once during Neovim configuration. All
options are optional.

Option                 Default       Description
                                                        *pi-nvim-options*
`position`             "tab"         Terminal placement: "tab", "horizontal",
                                     or "vertical".
`command`              "pi"          Executable command as a string or a list
                                     of arguments. Provider and model options
                                     are appended when configured.
`provider`             nil           Initial Pi provider; requires `model`.
`model`                nil           Initial Pi model.
`cwd`                  nil           Pi working directory. Defaults to the
                                     current Neovim working directory.

Example:

    require("pi_nvim").setup({
        position = "vertical",
        cwd = vim.fn.expand("~/src/my-project"),
        command = { "pi", "--verbose" },
        provider = vim.env.LLM_PROVIDER,
        model = vim.env.LLM_MODEL,
    })

A string `command` may also be used, for example `command = "pi"`. When
`provider` is set without `model`, setup raises an error. pi-nvim does not
install any key mappings; define any desired mappings in your Neovim config.

==============================================================================
3. Commands                                              *pi-nvim-commands*

pi-nvim installs no key mappings by default. Define any desired mappings in
Neovim's configuration.

                                                        *:Pi*
:Pi                     Open or focus the managed Pi terminal; from that
                        terminal, return to the window used to open it. With
                        a prompt, insert it into Pi's input and focus the
                        terminal. This command is named `Pi`; lowercase `:pi`
                        is not an alias. The default placement is a new tab.

:Pi {prompt}            Insert the prompt into Pi's input. In Visual mode, the
                        selected text and its source location are appended as
                        context. Run `:Pi` in Visual mode without a prompt to
                        transfer only the selection. Input is not submitted;
                        press Enter in Pi when ready.

                                                        *:PiReferences*
:PiReferences           Open the latest Pi References quickfix list, if one is
                        available. The list is not opened automatically.

When a managed terminal window is closed, pi-nvim stops its process and
removes its terminal buffer rather than keeping a hidden session for reuse.
Using `:Pi` from the terminal returns to the previous window and leaves the Pi
window open, so the session remains running.

==============================================================================
4. Selection transfer                                      *pi-nvim-selection*

Run `:Pi {prompt}` from a characterwise, linewise, or blockwise Visual
selection to add both the prompt and selected text to Pi's input. The
selection is captured before focus changes, along with its source and inclusive,
1-based line range. A named file buffer is identified as a file and uses its
absolute path. Other buffers are identified as buffers by name; an unnamed
buffer uses a label containing its buffer number. Run `:Pi` without a prompt in
Visual mode to transfer only the selection.

If there is no managed Pi process, the command starts one and waits for its
companion extension socket before delivering the prompt and context. They are
inserted into Pi's visible input but not submitted; the caret remains in the
editor so you can review or modify the text and press Enter when ready.

The transfer uses the extension's interactive editor API and requires a Pi
session with an interactive UI. If extension startup or delivery fails,
pi-nvim reports an error; extension readiness failures are also reported in
Neovim.

==============================================================================
5. Pi References                                          *pi-nvim-references*

After a completed assistant response without tool results, the extension
recognizes these file reference forms:

    path:line
    [label](path)
    [label](path:line)

Markdown file links without a line target line 1. Relative paths are resolved
against Pi's working directory. The list is replaced using references from
the latest eligible response; a response without recognized references
clears stale entries. Duplicate path-and-line entries in one response are
listed once.

The quickfix list is titled "Pi References" and remains closed until
`:PiReferences` is run. Press Enter on an item in the quickfix window to open
its file at the referenced line. Updates are routed over the managed session's
socket to its Neovim instance.

Reference parsing is intentionally limited to `path:line` and Markdown file
links. Vim help tags and other reference formats are not currently supported.

==============================================================================
6. Troubleshooting                                  *pi-nvim-troubleshooting*

Pi extension is unavailable
                        Ensure `~/Projects/pi-nvim/pi/index.ts` is listed in
                        Pi's `extensions` setting and inspect Pi startup
                        output for extension load errors. Prompt/selection transfer
                        and reference updates need the extension; `:Pi`
                        terminal management without input does not.

Pi references do not appear
                        Check that the companion extension loaded and that
                        the latest completed response contains a supported
                        `path:line` reference or Markdown file link.
